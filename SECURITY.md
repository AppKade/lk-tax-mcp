# Security and privacy

This development preview serves stdio on the user's device. It has no runtime network client, URL fetching, telemetry or RAMIS access. Local document and encrypted-draft capabilities are disabled unless the operator configures dedicated roots and a private key file. The adapter is the only application module permitted filesystem/subprocess capabilities. It runs fixed local Poppler/Tesseract commands without a shell, with bounded inputs/output and a shared time limit. The Node process and native dependencies are not an OS sandbox.

Never send identifiers, raw documents, paths containing personal names, credentials, keys or ciphertext into chat or tax facts. Document tool arguments contain a selected relative path visible to the host, but raw extracted text is not returned. Only schema-whitelisted amounts, years, page references, warnings and pseudonymous handles enter the source ledger. Every inclusion and applied total requires confirmation; malicious text is untrusted evidence, never instructions. Unknown layouts or poor OCR require review rather than guessed values. Unexpected fields and arbitrary free-text facts remain rejected; errors never echo paths, exception messages or subprocess diagnostics.

The user's host receives inputs and outputs, including amounts. A cloud host may send these to its provider. Other installed tools may access the conversation. Use a fully local host/model when that boundary matters. The server does not control the host's retention, logging or other tools.

Ordinary facts and consent stay in memory. Optional draft saves explicitly encrypt typed facts and redacted evidence metadata with AES-256-GCM and a locally configured private key; raw documents, source paths, consent and approvals are excluded. Authentication, expiry, active rules, schemas and ledger consistency are checked before atomic restore. Restore never restores prior consent or worksheet approval. Draft expiry is a restore deadline, not automatic deletion. A memory wipe does not delete ciphertext; delete saved slots separately. Key theft, backups, swap, crash dumps and physical erasure remain outside this guarantee. OCR temporarily writes raster pages in a private directory and attempts cleanup.

Every calculation revalidates current scope; missing exclusion answers cannot default to false. A known exclusion stops intake without collecting remaining scope or financial facts. Missing money never defaults to zero. Confirmed zero foreign amounts may make eligibility booleans irrelevant; neutral computation booleans for that proven-inapplicable branch are never stored as user answers. Editing amounts reactivates required confirmations. Unsupported scenarios refuse rather than silently omit income. Estimates are unreviewed and must not be used as filing outputs. Eligibility of foreign income and credit claims, manual FX conversion, donations, rent, solar claims and dividend finality is user-confirmed and is not independently verified; conflicting charity-cap results and dividend withholding mismatches stop calculation.

Report suspected vulnerabilities privately through GitHub's private vulnerability reporting if enabled, or contact the repository owner privately. Do not publish personal data, real certificates or credentials in issues.

The [threat model](https://github.com/AppKade/lk-tax-mcp/blob/main/docs/threat-model.md) records application, host, dependency and OS boundaries, the dated OWASP MCP risk mapping and residual risks. `npm run security:check` checks application-source capabilities in CI. Private package validation generates a production CycloneDX SBOM and compares it with the isolated installation's recorded inventory and integrity. These checks are review aids, not a sandbox, vulnerability scan, signature or guarantee of tax correctness.

See [local workflow](docs/local-workflow.md) for setup, native dependency requirements, configured-directory boundaries, key protection and remaining legal/filing limits.
